# Runbook

## Layout

| Path | Holds | Edited by |
| --- | --- | --- |
| `registry/` | Identity only: jurisdictions, orgs, persons, posts, tenures, external IDs | `lidx` commands, reviewed |
| `decisions/` | `same_as.csv` (merges), `overrides.csv` (reviewed rulings, including `allow-address`) | V |
| `observations/YYYY/MM/` | One JSONL file per collection run; append-only | `lidx` commands |
| `schema/` | `schema_version`, `allowlist.json` (privacy boundary as code) | V |
| `data/firms.csv` | The firm table, generated by `lidx build` | Build only |
| `build/` | `index.db` and `firms.html` (gitignored; may hold sales notes) | Build only |
| `leads/YYYY/MM/` | News posts worth a look, from `collect-feeds` (gitignored; never facts) | Collector code |
| `schema/feeds.json` | Feed sources, search terms and headline filters | V |

## Commands

```
cargo run -- validate [--base origin/main]   # schema, registry, allowlist, append-only
cargo run -- build [--sales ~/legal-sales.db] # derive facts; write db, firm table, page
cargo run -- ingest-firms <file.csv> --at YYYY-MM-DD
cargo run -- ingest-offices <file.csv> --at YYYY-MM-DD  # public offices: orgs, posts, holders
cargo run -- ingest-bar <file.csv>            # credential lookups for people already in the registry
cargo run -- collect-dns                      # mail, SPF and DMARC for every firm with a website
cargo run -- collect-feeds [--since YYYY-MM-DD]  # Governor and newspaper search APIs -> local leads
cargo run -- sales-init ~/legal-sales.db      # creates the local sales database (outside the repo)
```

## How a fact becomes current

1. A run writes observations: source, date read, entity, field, value, URL, confidence.
2. The build groups identical values into assertions with first-seen and last-confirmed dates.
3. The current value per field is chosen by: reviewed override, then higher confidence, then most recently confirmed.
4. Merges are rows in `decisions/same_as.csv`, applied at build time; undo by deleting the row.

| --- | --- |

## Leads

`collect-feeds` keeps a post only if it names someone already in the registry or its headline contains a legal term. Leads stay on your machine: headlines can name people in criminal matters, and git history is permanent. To act on a lead, read the article, then add what it establishes (an appointment, a retirement) through an ingest CSV with the article URL as the source.

## When something breaks

- **Validation fails:** read the error; fix the input, never the observation history.
- **A collector sees a challenge page, a changed form, or a result count equal to the cap:** stop; do not ingest; note it here with the date.
- **A wrong or harmful value was committed:** add a correcting observation or an override. If it is excluded data (a home address, family detail), remove it from history with `git filter-repo`, force-push, and re-clone every copy.
- **Pause everything:** create an empty file `PAUSED` at the repo root; collectors must refuse to run while it exists.

## Sales data

Never in this repo. `lidx sales-init` creates a local SQLite file elsewhere with `firm_sales`, `contact_log` and `do_not_contact`, keyed by the org IDs in `registry/orgs.csv`. Pass it to `lidx build --sales` to add notes to your private page; the page then says not to share it.
